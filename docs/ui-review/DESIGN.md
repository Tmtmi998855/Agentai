# 아데어 UI 시안 디자인 기준

이 문서는 `docs/ui-review/review.html`의 오프라인 제품 시안 및 로컬 Mock API 연동 화면을 위한 기준이다. 실제 제품 디자인 시스템, 브랜드 가이드, API 계약이 아니다. 이 화면은 로컬 Mock API(`/ui-review` 경로)와 연동하여 비동기 브리핑 생성 요청(POST /v1/briefings) 및 폴링을 시연하며, 실제 공개정보 수집 및 외부 LLM은 연동되어 있지 않다(`MOCK_VIRTUAL` provenance). Vercel 정적 배포는 오프라인 샘플 검토용이며, 라이브 로컬 API 연동은 FastAPI 동일 출처 `/ui-review`에서만 작동함을 구분한다.

## 0. 참고 스타일과 적용 범위

- 제공된 두 모바일 화면은 **스타일 참고**로만 사용한다. 밝은 중성 앱 배경, 흰색 둥근 카드, 얕은 그림자, 촘촘한 정보 위계, 청록·하늘색 포인트와 연보라 보조 면을 추출한다.
- 원본 은행 화면의 로고, 상품명, 금융 문구, 고유 아이콘, 수치, 화면 복제는 하지 않는다. `아데어`의 브리핑 흐름과 가상 데이터만 표현한다.
- 제품의 읽기 순서는 `회사 개요 → 실적/재무 추이 → 최근 회사 이슈 → 산업/시장 이슈 → 영업 전략(수요 가설 · 미팅 질문 · 대화 시작) → 출처`다. 기업 메타는 회사 개요 카드 안에 포함한다.
- 상단 기본 화면에 `지필로스 · MOCK_VIRTUAL` 시안 및 사용자 제공 맥락(웹사이트 www.g-philos.co.kr, 제안 상품 법인 장기렌트카, 미팅 부서 경영관리팀, 담당 역할 차량 담당자, 미팅 목적 법인 차량 운영 현황 및 장기렌트 도입 검토)과 검증된 공개정보 경계를 명확히 표시한다. 개발용 샘플·폭 전환은 기본 화면을 가리지 않는 native `details` 안에 둔다.

## 1. 토큰

CSS의 색상·간격·반지름·깊이는 아래 토큰으로만 사용한다.

```text
--canvas: #eef2f4             앱 배경
--surface: #ffffff            기본 카드
--surface-soft: #f6f8fa       보조 면
--ink: #162b35                본문
--ink-soft: #58707a           보조 글자
--line: #dbe5e8               얇은 경계
--teal: #087f83               핵심 청록
--sky: #dff5f7                청록·하늘색 강조 면
--sky-strong: #24b6c2         핵심 행동 강조
--lilac: #f0eafd              가능성·확인 필요 면
--lilac-line: #aa98e6         가설 왼쪽 경계
--danger: #a94450             오류 텍스트
--danger-soft: #fff1f3        오류 면
--focus: #087f83               키보드 포커스
--space-1/2/3/4/5: 8/12/16/24/32px
--radius-card: 22px            제품 카드
--radius-small: 14px           반복 블록
--shadow-card: 0 12px 28px rgba(30, 66, 78, .08)
```

본문은 시스템 한글 글꼴(`맑은 고딕`, `Malgun Gothic`, `Apple SD Gothic Neo`, sans-serif), 15px/1.6을 사용한다. 제목은 24~34px, 섹션 제목은 18~21px, 보조 정보는 12~13px로 구분한다. `word-break: keep-all`과 URL·기술 문자열용 `overflow-wrap`을 유지한다.

## 2. 컴포넌트와 상태

- **입력 폼 컴포넌트 및 상태**:
  - 필수 항목: `company_name` (기본값: 지필로스), `sales_profile.company` (아데어), `industry` (모빌리티·렌터카), `product_service` (법인 장기렌트카), `target_customer` (법인 차량 운영 기업), `sales_goal` (법인 장기렌트 도입 상담)
  - 선택 항목: `meeting_context.department` (경영관리팀), `role` (차량 담당자), `meeting_purpose` (법인 차량 운영 현황 및 장기렌트 도입 검토), `past_notes` (빈 값)
  - 기본값으로 수정 가능한 `MOCK_VIRTUAL` 기본 폼 데이터를 채우되 명시적 `label`, `input`, `textarea`, `button` 구조를 유지한다.
  - 제출 버튼 텍스트 상태: `분석 준비` (idle), `분석 중` (submitting / PENDING / RUNNING), `완료` (COMPLETED), `오류` (FAILED).
  - 작업 진행 상태: `idle`, `submitting`, `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`를 지원하며, 중복 제출 방지(disabled 처리)와 `aria-live="polite"` 알림을 제공한다.
- **모션 및 시각 효과**:
  - 새 라이브러리/외부 폰트/외부 자원 없이 브라우저 기본 CSS만 사용한다.
  - 버튼 및 상태 변경 시 짧은 opacity/color 색상 전환(transition)만 사용하며, `prefers-reduced-motion: reduce` 시 전환을 비활성화한다.
- **제품 헤더**: 서비스명 `아데어`, 짧은 한 줄 설명, 지필로스 MOCK_VIRTUAL 시안 고지 및 사용자 제공 맥락 표시. 한 번에 제품 목적과 사용자 제공 정보를 이해하게 한다.
- **브리핑 카드**: 흰색, `22px` 반지름, 얕은 청록 계열 그림자, `24px` 안쪽 여백. 카드 안의 반복 블록은 `14px` 반지름과 얇은 선을 사용한다.
- **회사 개요 카드**: 회사명·확정 법인·업종·지역·식별 신뢰도 및 웹사이트(www.g-philos.co.kr 등)를 메타 행으로 보여준다.
- **실적/재무 추이**: API 계약에 재무 시계열이 없으므로 숫자/그래프 수치를 날조하지 않고 '공개적으로 확인 가능한 재무 추이 자료가 없습니다.' 빈 상태를 보여준다. 차트 영역 틀/범례는 가능하나 데이터 선/막대/수치는 금지한다.
- **최근 회사 이슈**: 실제 계약의 sources를 날짜 순서(published_at)로 카드화하여 제목/날짜/요약/링크를 보여준다. 가상 출처임을 밝힌다. sources가 없으면 빈 상태다.
- **산업/시장 이슈**: 현재 계약에 구분된 산업 동향 필드가 없으므로 '실제 공개정보 조사 후 표시됩니다.' 빈 상태를 표시한다.
- **영업 전략**: `demand_hypotheses`, `meeting_questions`, `small_talk`을 한 섹션 아래 세부 하위 블록으로 구별해 배치한다. 모든 수요 가설에는 `HYPOTHESIS · 미팅에서 확인` 배지와 가능성 면(연보라)을 적용한다.
- **출처**: 기본 접힘 native `details`; 가상 출처와 FACT 역할 고지를 펼침 영역 상단에 둔다.
- **검토 도구**: 샘플 6개 버튼과 폭 3개 버튼을 상단 native `details`에 접는다. 버튼은 `aria-pressed` 상태를 유지한다.
- **오류·보류**: 오류·근거 부족·기업 식별 보류는 색상과 텍스트를 함께 사용한다. 실제 선택·재시도 CTA는 만들지 않는다.

## 3. 반응형 규칙

- 기본은 모바일 우선이며 페이지 좌우 여백은 16px, 카드 안쪽 여백은 20~24px이다.
- 375px 모바일에서는 회사 개요 → 실적/재무 추이 → 최근 회사 이슈 → 산업/시장 이슈 → 영업 전략 → 출처 순서로 세로 흐름을 유지한다.
- 768px 이상에서는 회사 개요와 실적/재무 추이를 2열 그리드로 보여줄 수 있다.
- 1280px에서도 본문 최대 폭(min(100%, 1280px))과 가독성을 유지한다.
- 비교용 미리보기 폭은 기존대로 휴대폰 375px·태블릿 768px·넓게 960px이다. 이는 기기 성능이나 실제 반응 속도 측정이 아니다.
- 640px 이하에서는 헤더·도구·제목을 세로로 쌓고, 긴 URL과 기술 상세만 어절 내부 줄바꿈을 허용한다.
- 560px 이하 브리핑에서는 수요 가설 제목과 가능성 배지를 세로로 쌓아 제목이 좁은 열로 깨지지 않게 한다.
- 가로 스크롤은 미리보기 프레임 내부에만 허용하며 제품 시안 본문은 viewport를 넘지 않는다.

## 4. 접근성

- `header`, `main`, `section`, `aside`, heading 순서를 유지한다.
- 샘플·폭 선택은 실제 `button`과 `aria-pressed`로 표현하고, 키보드 포커스는 청록 3px outline으로 표시한다.
- 상세 정보와 출처는 native `details`/`summary`를 사용한다. 기술 정보는 기본 접힘이다.
- 오류·경고는 색상만으로 구별하지 않고 제목과 설명을 함께 제공한다.
- `lang="ko"`, 명시적 버튼 타입, `aria-live="polite"`, reduced-motion 대응을 유지한다.
- 아이콘이 필요할 때는 장식용 인라인 SVG만 사용하며 의미 있는 텍스트를 대체하지 않는다.

## 5. 프로토타입 제약과 허용된 부채

- embedded JSON 6종과 값은 원본 샘플과 동일하게 유지한다. 기존 `render`/DOM 생성 흐름을 재사용한다.
- 정적 HTML 한 파일, 인라인 CSS/JS, 새 패키지·프레임워크·외부 폰트·외부 네트워크 호출을 추가하지 않는다.
- Vercel 정적 배포 등 오프라인 정적 환경에서는 6종 샘플 검토 기능을 제공하며, 실제 API 제출 시 "로컬 Mock API 화면(/ui-review)에서 실행" 안내를 표시한다.
- 라이브 로컬 API 연결은 동일 출처 FastAPI의 `/ui-review` 경로에서만 수행되며 CSP `connect-src 'self'`로 외부 연결을 엄격 차단한다.
- 실제 제품 성능, Lighthouse 100, 질문 유용성, “3분 읽기” 분량은 이 시안에서 주장하거나 측정하지 않는다.
- 남은 부채는 실제 데이터가 연결될 때 색상 대비와 긴 회사명·출처 문자열을 실데이터로 다시 검증하는 것이다. 이 검토 단계에서 서버·콘텐츠·분석 로직은 수정하지 않는다.

## 6. 검증 기준

- `node --check`로 inline JS를 확인한다.
- embedded JSON의 6개 샘플 키·값이 변경되지 않았는지 원본 해시로 확인한다.
- `git diff --check`를 통과해야 한다.
- 375/768/1280px에서 가로 넘침이 없고, 샘플 전환·폭 전환·details 펼침·키보드 포커스가 유지되어야 한다. 실제 기기·실제 분석·네트워크 동작 검증은 하지 않는다.
